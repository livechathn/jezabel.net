// the screen is a file

linux exposes the GPU's backlight as a regular file under /sys/class/backlight/. write a number, brightness changes. instantly. no daemon, no API, no GUI.

/sys/class/backlight/intel_backlight/brightness is the lever. write 0 → screen black. write max_brightness → screen back. first read the max to know your range:

step 1 — discover your max:
cat /sys/class/backlight/intel_backlight/max_brightness
↓ prints e.g. 96000
step 2 — write to brightness:
0 → brightness = screen off
96000 → brightness = screen on

// the sudo tee dance

everyone trips on this. you try sudo echo 0 > brightness and get "permission denied". but you used sudo. what gives?

the > redirect is interpreted by your shell, not by echo. and your shell runs as you — not as root. sudo only elevates the command after it, which here is echo. the file open for write happens before sudo gets a turn.

the trap:
sudo echo 0 > /sys/.../brightness
↓ shell (as YOU) opens brightness for write
✕ permission denied — root-only file
the fix:
echo 0 | sudo tee /sys/.../brightness
↓ shell pipes 0 to sudo tee (still as YOU, but pipe is allowed)
↓ sudo elevates tee to ROOT
✓ tee (as root) writes 0 to brightness

tee is a tiny unix program that reads stdin and writes it to both stdout and any files you name. when you pipe through sudo tee, the writing program runs as root. the redirect problem is gone.

primary
intel_backlight
on most intel laptops: /sys/class/backlight/intel_backlight/.

AMD systems: usually /sys/class/backlight/amdgpu_bl0/.

if neither exists, list /sys/class/backlight/ — whatever's there is yours.
range
max_brightness
cat .../max_brightness first.
you'll see something like 96000 or 7500.

your accepted writes are 0 through that max. out-of-range values silently clamp.
deeper
fb0/blank
/sys/class/graphics/fb0/blank goes one layer deeper:

0 = unblank (on)
1 = blanked
4 = full powerdown

deeper than backlight — affects the framebuffer itself.
trap
setterm + ssh
setterm --blank 1 blanks the tty after 1 min idle.

over ssh it controls your ssh pty, not the physical console.

to blank the real screen: setterm --blank 1 > /dev/tty1.
permanent
consoleblank=N
pass consoleblank=N as a kernel boot argument (N = seconds idle before blank).

edit /etc/default/grub → update-grub.
survives every reboot.
why
headless laptop
the most common use: a battery-less laptop running as a server.

close the lid = suspend = death. set HandleLidSwitch=ignore in /etc/systemd/logind.conf.

pair with this lesson: lid stays open, screen stays off.

backlight doctrine

  • never sudo echo > file — the redirect runs before sudo. shell opens the file as you. perm denied.
  • always echo X | sudo tee path — tee is the writer; sudo elevates tee, not echo.
  • cat max_brightness first — don't guess. the value differs across panels (96000 / 7500 / 100).
  • setterm over ssh = wrong target — point at /dev/tty1 for the physical console.
  • consoleblank=N for permanent — kernel boot arg survives reboot, no daemon needed.
  • headless laptops need this — paired with HandleLidSwitch=ignore, the lid stays open and the screen stays off.
