// what is a symlink

a symbolic link is a pointer. a ghost file that says: "the real thing lives over there." linux follows it transparently — the system sees the destination, not the link.

think of it like a portal. /usr/local/bin/telegram is the door. /opt/Telegram/Telegram is where the room actually is.

you type: telegram
↓ shell resolves PATH → finds:
/usr/local/bin/telegram SYMLINK /opt/Telegram/Telegram (real binary)
↓ executes actual binary

the binary lives in /opt — your territory for third-party installs. the symlink lives in /usr/local/bin — on every user's PATH. clean separation. zero pollution.

concept
soft vs hard link
soft (symlink) — points to a path. if original is deleted, link breaks. crosses filesystems. use this always.

hard link — points to raw inode on disk. deletion-proof. can't cross filesystems. rarely needed.
syntax
ln -sf explained
ln -sf [TARGET] [LINK_NAME]

-s → symbolic (soft) link
-f → force (overwrite existing)

target = real file. link_name = alias you invoke. order matters — don't flip them.
filesystem
where things belong
/opt/AppName/ → third-party app binaries
/usr/local/bin/ → manual symlinks (system-wide)
~/.local/bin/ → per-user, no sudo needed

apt never touches /usr/local. your zone.
danger
broken links
move or delete the target → symlink turns ghost.
find /usr/local/bin -xtype l lists all broken.

always use unlink or rm to remove — never rm -rf on a symlinked directory.
pattern
version switching
keep /opt/Telegram-v1/ and /opt/Telegram-v2/.
update is one command:

ln -sf /opt/Telegram-v2/Telegram /usr/local/bin/telegram

rollback = same command, old path. zero downtime.
inspect
read a symlink
ls -la /usr/local/bin/telegram
shows the → arrow pointing to target

readlink -f /usr/local/bin/telegram
resolves full absolute path, even chained links

symlink doctrine

  • target first, link second — ln -sf [real] [alias]. never reversed.
  • /opt is sacred — drop all manual binaries there. apt can't touch it.
  • always use -f — silently overwrites stale links. no drama.
  • inspect before you trust — ls -la to verify before executing anything.
  • never rm -rf a symlinked dir — it follows the link and destroys the target.
  • broken links are silent killers — audit with find -xtype l regularly.
